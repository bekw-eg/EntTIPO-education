# Этап 5: план дня и подтверждённая проработка

Проверенная база этапов 1–4 — `291b766`: подписанные аккаунты, сохраняемые
тренировки, UUID отправок, явный каталог навыков и отдельная диагностика.
Ранее isReviewed означал отметку разбора, а «похожая задача» запускала
обычную тренировку по теме. Это не доказывало самостоятельное освоение.

## План и календарь

`GET /api/learning-plan` сохраняет один план на аккаунт и календарную дату
YYYY-MM-DD. Зона из User.timeZone; по умолчанию Asia/Qyzylorda. Настройка
доступна на главной и через PATCH /api/user { timeZone }. Созданный план
сохраняет свою зону. При возврате в уже существующую дату после смены зоны
возвращается прежний план с прежними отметками. Новый день начинается в
местную полночь. Intl-границы учитывают дни 23/25 часов. Карточка обновляется
при фокусе и раз в минуту; даты главной и ежедневные счётчики тоже используют
зону ученика.

Если размеченных наблюдений нет, предлагается входная диагностика. После
завершения её действие остаётся выполненным, а план автоматически добавляет
три учебных действия: одно конкретное правило, три задачи и одну проверку.
Уже отправленные сегодня задачи выбранного навыка засчитываются в три
задачи практики. Это выполнение действия, а не подтверждение навыка.

Выбирается один навык. Вес ранжирования: наступившее повторение 200;
состояние weak 80; недавняя неподтверждённая ошибка 30 (до 90); неточный
ответ последней диагностики 20 (до 60); подсказка за 14 дней 12 (до 36);
давность практики до 30; низкая оценка (100 − оценка)/10. Равенства — по ID.
Причины сохраняются и объясняются на русском и казахском. Если пробелов не
обнаружено, предлагается повторение и сложность на один уровень выше
последней с близкими вариантами ±1; повышение зависит от наличия банка.
Список вопросов сохраняется, при обновлении случайного перевыбора нет.

Начатая вчера незавершённая практика/проверка переносится с тем же sessionId
и оставшимися действиями небольшого плана. Выполненные действия остаются в
архиве. Если тренировка вчера не была начата, план архивируется и новый
выбирается по актуальным данным. Активная диагностика возобновляется через
существующую сессию. История не удаляется.

После новой диагностики пересчёт разрешён, пока не отмечено чтение правила
и не создана тренировка. Старые неначатые действия становятся superseded.
Начатый план не переписывается; новые результаты применяются в новом плане,
но перенос незавершённой работы имеет приоритет. Повторная диагностика
запускается явно: POST /api/diagnostics { restartFromId }. Уникальная пара
аккаунт/исходная диагностика защищает запуск от дублей, даже после завершения.
Задания повторяются; новые наблюдения имеют увеличенный attemptNumber и не
считаются свежими независимыми доказательствами.

## Подтверждение ошибки

isReviewed/reviewedAt сохраняют только просмотр разбора. PATCH разрешает
менять только этот флаг. Просмотр объяснения, ИИ-разбор, чтение правила,
завершение сессии и повтор исходной задачи не записывают confirmedAt.

POST /api/mistakes/:id/check и проверка плана создают/возобновляют одну
сохранённую сессию. LearningCheck связывает аккаунт, исходную ошибку, навык,
другую задачу, сессию и её первую проверенную попытку. Подтверждение требует:

- другой ID задачи, явную связь вопроса и шага с тем же навыком;
- сложность ±1 от исходной задачи (или выбранной сложности самопроверки);
- правильное решение всех шагов;
- отсутствие предыдущих попыток этой задачи у аккаунта;
- отсутствие подсказки/ИИ-помощи на эту задачу в любой сессии, включая
  запросы помощи без sessionId;
- принадлежность попытки сохранённой проверке и тому же аккаунту.

Проверочный вопрос исключается из предварительной практики. Добавлено
30 вариантов: 12 для практики, 18 с purpose=verification, которые обычная
тренировка не расходует. При неудаче сохраняется неудачная проверка; для
новой проверки требуется другой ещё не раскрытый вопрос. Повтор уже
показанного эталона не подтверждает ошибку. Если подходящего задания нет,
выводится честное состояние и подтверждение не записывается. Старые ошибки
без skillId не размечаются по догадке из темы или приблизительной метки.

В транзакции оценивания записываются confirmedAt, confirmationAttemptId,
исход проверки и расписание. Подтверждается только целевая ошибка. Раздел
ошибок различает просмотр, подтверждение и наступившее повторение, показывает
следующую дату и ссылку на подтверждающую тренировку.

## Повторения и дубли

Внутренняя педагогическая эвристика — 1, 3, 7, 14 дней; оптимальность не
гарантируется. Первая самостоятельная проверка назначает один день.
Успешное самостоятельное повторение в наступивший срок увеличивает интервал;
после 14 дней он остаётся 14. Новая проработка другой ошибки того же навыка
начинает с одного дня. Ошибка или зарегистрированная помощь возвращает
интервал к одному дню; факт прошлого подтверждения остаётся в истории.

SkillReview уникален по аккаунту/навыку. dueDay и timeZone хранятся вместе;
интервал считается от местной даты попытки. Новые назначения используют
текущую настройку ученика; уже назначенная дата сохраняет свою зону. Версия
расписания не позволяет устаревшей параллельной проверке увеличить интервал
второй раз. Блокировка аккаунта, уникальные UUID, связь проверки/сессии и
идемпотентная запись помощи предотвращают повторные записи при дублях.

## Миграция и проверки

Остановить приложение, выполнить, затем запустить снова:

```powershell
npx prisma db execute --file prisma/updates/20261004_daily_learning_plan.sql --schema prisma/schema.prisma
npm run db:generate
npm run db:skills
```

SQL добавляет таблицы и nullable-поля, работает транзакционно и допускает
повторное применение. Старые попытки, тренировки, диагностики, ошибки и
isReviewed сохраняются; фиктивные подтверждения не присваиваются. Старые
hintedQuestionIds учитываются и без QuestionHelp. db reset не нужен.

test:plan:unit проверяет ранжирование, самостоятельность, RU/KK, местную
полночь, високосный год, переход года и дни 23/25 часов. test:plan использует
реальные API/PostgreSQL и четыре изолированных аккаунта: конкурентные запросы,
повторный вход, сохранение/перенос черновика, просмотр/повтор/помощь, конкретное
подтверждение, интервалы, пересчёт после диагностики и повторную миграцию.
Тесты удаляют только созданные ими данные.

## Ограничения

Каталог содержит три размеченных навыка. Банк конечен: после раскрытия всех
подходящих вариантов проверка недоступна до пополнения. Помощь вне платформы
достоверно выявить нельзя. Сходство определяется навыком и сложностью,
отдельная таксономия подтипов пока не введена. Офлайн-оценивание не добавлено.
Английская локаль новых экранов использует русский текст. Полная история
наблюдений пока читается целиком: для большой нагрузки потребуются замеры
и оптимизация выборок. Порогам и интервалам нужна педагогическая калибровка.
