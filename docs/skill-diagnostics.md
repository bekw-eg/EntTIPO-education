# Этап 4: диагностика навыков

Входная диагностика доступна на `/diagnostics` из навигации и страницы практики.
Она содержит 9 заданий: по три на свойства степеней, цепное правило и знаки
при раскрытии скобок. После завершения доступны конкретные ошибки, ответы,
разбор, правило для повторения и кнопка запуска подходящего задания.

## Обновление существующей базы

Остановить приложение, выполнить команды и запустить его снова:

```bash
npx prisma db execute --file prisma/updates/20261004_skill_diagnostics.sql --schema prisma/schema.prisma
npm run db:generate
npm run db:skills
```

SQL выполняется транзакционно и может применяться повторно. `db:skills`
добавляет каталог, 9 заданий диагностики и 10 заданий практики, включая одну
задачу на два навыка. Повторный запуск не изменяет существующие задания,
ответы, попытки, ошибки, результаты и позиции сессий. Для первоначального
создания базы достаточно `db:push` и `db:seed`. Для обновления истории
используется именно `db:skills`, а не первоначальный демонстрационный сид.

## Проверка банка и прежних эвристик

До изменения локальный банк содержал 426 задач. Проверены исходные задания
`prisma/seed.ts`, алгоритмические генераторы и их сохранённые шаги.

| Прежнее место | Проблема | Новое поведение |
| --- | --- | --- |
| `app/api/attempts/route.ts`, `inferWeakSkill` | Название темы/подстроки в заголовке подменяли конкретный навык | Только сохранённые связи `StepSkill` |
| `lib/adaptive.ts`, `getQuestionsForWeakSkills` | Поиск слов из `weakSkill` в заголовке/условии | Связи `QuestionSkill` по стабильному `skillId` |
| `app/api/mistakes/route.ts` | Произвольные старые названия и Mastery темы выдавались за Mastery навыка | Только каталог и отдельные наблюдения навыка; при недостатке данных оценка скрыта |
| `lib/questionGenerator.ts` | Приблизительное сопоставление строк и не сохранявшиеся теги | Явные идентификаторы в данных генератора; точные ключи/совместимые старые алиасы |

Для свойств степеней проверены `q2_t1` (дробная степень) и `q3_t1`
(умножение степеней). Шаг арифметического сложения показателей отдельно
не помечается свойствами степеней. Исходные ID привязываются только при
совпадении проверенных эталонов шагов. В сохранённых вариантах генератора
привязывается шаг выбора формулы `a^m * a^n = a^(m+n)` по точной сигнатуре
шага и правильного варианта. Обычные вычисления отдельно не помечаются.

Задачи на объём пирамиды, попавшие в тему `t1` в прежнем генераторе банка,
не получают навык степеней. Производная `x^n` не получает цепное правило.
Квадрат суммы, разложение многочлена и разность кубов не получают навык
смены знаков при отрицательном множителе. Для последних двух навыков
добавлены самостоятельные задания, которые действительно их проверяют.

Старые `weakSkill` сохранены как исторические данные. Миграция не назначает
им `skillId` и не переоценивает старые ответы по догадке. Даже после
проверенной привязки самой задачи историческая ошибка без конкретного
шага остаётся без конкретного навыка. Старые попытки продолжают участвовать
в прежнем прогрессе тем. Наблюдения навыков собираются с новых решений.

## Расчёт прогресса

`SkillObservation` содержит результат только тех шагов, которые явно связаны
с навыком. Например, верные степени и неверные знаки в одной задаче дают
100% для степеней и 0% для знаков, а не общий балл 50% каждому навыку.
Несколько шагов одного навыка дают одно наблюдение с частичным баллом.

Используется тот же `calculateMasteryScore`: последние десять наблюдений,
больший вес новых ответов, сглаживание 70/30, штраф 15 за подсказку и 10
за каждый повтор. Прогресс тем и прежняя нумерация попыток не изменены.
Для навыков дополнительно учитываются повторы той же задачи между сессиями.

Между результатами и после последнего результата балл затухает с периодом
полураспада 90 дней. Наблюдения старше 90 дней не попадают в текущие окна
новых результатов. При менее чем трёх разных заданиях за 90 дней состояние
`insufficient`: интерфейс показывает «Недостаточно данных», а не процент.
«Освоено» требует балла не ниже 85, минимум пяти разных недавних задач
и четырёх разных самостоятельных верных первых решений. Подсказки и
повторные решения не считаются самостоятельными успехами.

API пересчитывает актуальную давность при чтении. `UserSkillProgress`
хранит последний рассчитанный снимок и обновляется в той же транзакции,
что новое наблюдение. Результат входной диагностики сохраняется как
исторический отчёт; актуальный прогресс показан отдельными карточками.

## Хранение и оценивание диагностики

`DiagnosticSession` хранит выбранные ID, порядок, позицию, ревизию,
незаконченный ответ и итог. `DiagnosticAnswer` хранит одну неизменяемую
отправку на задание. Все записи привязаны к владельцу сессии. Блокировка
аккаунта сериализует параллельные запросы, ревизия отклоняет старые записи.

Запуск повторно открывает незавершённую диагностику или её сохранённый
итог. Отправка требует UUID; повтор с тем же UUID и ответом возвращает
тот же нейтральный чек приёма. Изменение ответа с тем же UUID и второй UUID
для уже решённого задания получают `409`. Ответ можно отправить только
на текущую позицию. Сохранение ответа и переход происходят атомарно.

Черновики используют проверенный в этапе 3 формат локальной копии с
ключом аккаунта и сессии, записью до автосохранения и UUID неподтверждённой
отправки. Ответ на сервере восстанавливается и с другого устройства.

До завершения API возвращает только условие, введённые ответы и позицию.
Нет эталонов, правильности, баллов, объяснений, подсказок и признаков
правильного варианта. AI не обслуживает диагностические ID, в том числе
если запрос не содержит ID сессии. Диагностические задачи исключены из
обычной подборки и не проверяются через `/api/attempts`.

После последнего ответа в одной транзакции сохраняются итог и наблюдения
навыков. Это отдельный режим: диагностика не создаёт обычные тренировочные
попытки, ошибки, дневную цель или прогресс тем. Таким образом обычные
тренировки сохраняют немедленное оценивание, подсказки и повторы.

## Объяснения и адаптивная практика

Известные неверные ответы имеют проверенные русские/казахские объяснения:
потерянный внутренний множитель, неверное действие с показателями или
неизменённый знак конкретного слагаемого. Для других ответов система
показывает расхождение с эталоном и прямо сообщает, что точная причина
по этому ответу неизвестна. Заключение ограничено наблюдаемыми заданиями.

Связи диагностической операции со следующей практикой заданы в
`DIAGNOSTIC_FOLLOWUPS`. Рекомендация проверяется по `QuestionSkill`, а
запуск практики также проверяет запрошенные `skillId` и `questionId`.
После диагностики слабые навыки получают гарантированные места в начале
смешанной подборки и приоритет в режиме слабых тем. При недостатке точных
связей остаётся прежний общий подбор по темам/историческим ошибкам.

```bash
npm run test:session:unit

```

API-тестам нужны PostgreSQL, SymPy (или встроенный валидатор) и запущенное
приложение. Они создают временные аккаунты, затем удаляют только свои
данные. Новый набор покрывает два аккаунта, пороги наблюдений, частичное
решение, подсказки и повторы, давность, отсутствие эталонов до завершения,
восстановление, конкурентные отправки, соответствие рекомендованной
операции и повторное применение миграции с сохранением старой истории.

## Ограничения

Первые три навыка и девять заданий — короткий учебный скрининг, не полная
оценка всей математики ЕНТ. Повторное прохождение входной диагностики
пока не добавлено: повторный запуск открывает существующий итог.
Для остальных навыков нужна отдельная проверенная разметка банка.
Русский и казахский поддерживаются в новом каталоге, заданиях диагностики
и отчёте; английский для этого этапа пока использует русский текст.
Сохранение на сервере и оценивание требуют соединения; полная офлайн-работа
остаётся отдельным этапом. Политика давности и пороги — прозрачные
эвристики, ещё не откалиброванные по статистике большого числа учеников.
