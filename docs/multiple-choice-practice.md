# Тренировки с выбором ответа A–E

Обычная тренировка показывает условие и пять вариантов. Ученик выбирает один
ответ и нажимает «Проверить». Для редких вопросов с несколькими ответами явно
показано «Выберите все правильные ответы», используются флажки. Проверка
такого вопроса даёт 100 только за полный набор без лишних вариантов, иначе 0.
Пошаговое решение доступно после проверки, вводить его не нужно.

Разбор после проверки оформлен как короткий урок: ответ, объяснение,
правило из существующих учебных данных и повторение. Причина без явной
разметки остаётся неизвестной и показывается одним общим уведомлением.
[Структура интерфейса и проверки](practice-result-analysis.md).

`PRACTICE_MULTI_MAX_PERCENT` задаёт предел от 0 до 5 процентов (по умолчанию 5).
Это максимум, а не целевая доля. Тренировки короче 20 вопросов, план дня и
самостоятельные проверки состоят из заданий с одним ответом. Банк не пополняется
вопросами с несколькими ответами для выполнения квоты. Экзамены сохраняют
четыре варианта и оценивание выбранной спецификации B057.

## Обновление существующей базы

Остановите приложение и примените добавочное обновление без reset:

```powershell
npx prisma db execute --file prisma/updates/20261005_multiple_choice_practice.sql --schema prisma/schema.prisma
npm run db:generate
npm run db:choices
```

Для новой базы `db:push`, `db:seed`, `db:skills`, `db:exam` подготавливают также
варианты. Скрипт расширения банка подключает тот же адаптер. Повторный запуск
миграции безопасен. Скрипт не удаляет пользователей, попытки, шаги, ошибки,
диагностику, экзамены или прогресс. Исходные ответы и шаги остаются неизменными;
новый `Question.practiceChoice` содержит отдельную версию учебного формата.
Старые текстовые черновики архивируются в `legacyDraftAnswers`. Условия с
неопределённым интегралом уточнены: требуется общий вид первообразных с C.
Старые округлённые объёмы пирамид в новом адаптере заменены точными дробями.

Каждая новая тренировка сохраняет приватную копию условия, объяснения, ключа и
один раз перемешанного порядка вариантов в `choiceSnapshots`. Сохранённые
копии не переписываются при обновлении банка. Существующие сессии сохраняют
идентификаторы вопросов, позицию и результаты; копия формата создаётся при
возвращении к вопросу. Старые проверенные шаги можно просматривать, а повторная
попытка выполняется выбором итогового ответа. История всех попыток доступна
после завершения тренировки. Непроверенный старый текстовый ввод архивируется;
ученик выбирает вариант для нового формата.

## Проверка, помощь и прогресс

Публичные ответы API собираются по списку разрешённых полей. Ключи правильности,
разметка ошибок, подробное решение и приватные копии сессии до проверки
отсутствуют. Сервер принимает идентификаторы вариантов; буквы A–E и текст
варианта не являются ответом. Порядок — только представление. Выбор хранится
в прежнем черновике с ключом `choice:<questionId>`: одиночный идентификатор или
JSON-массив идентификаторов для флажков. Немедленная локальная копия и серверная
версия сохраняют прежнюю защиту от потери работы и конфликтов вкладок.

UUID отправки, исходный запрос и результат сохраняются в одной транзакции с
прогрессом. Повтор того же UUID возвращает исходный результат; изменённые данные
отклоняются. Новый UUID не позволяет повторно сохранить уже проверенный вопрос:
для новой попытки требуется действие «Попробовать ещё раз». Отвечать за другого
пользователя или на вопрос не в текущей позиции нельзя.

До ответа помощь по вопросу ограничена авторской концептуальной подсказкой;
свободный запрос AI и уровень подсказки не открывают подробное решение.
Использование подсказок сохраняется. Mastery Score, давность, штрафы за повтор,
расписание повторений, независимые проверки и уникальные счётчики используют
прежние алгоритмы. Неверный выбор получает конкретную причину только при явной
разметке варианта; иначе `unclassified`. Наблюдение навыка связано с явно
размеченным учебным вопросом, а не с угаданной причиной ошибки.

Новые офлайн-пакеты содержат пять вариантов без ключей. Без сети ответ сохраняется
в очередь с отметкой «Ожидает проверки»; результат и объяснение приходят после
серверной синхронизации. Сохраняется прежний учёт офлайн-ответов как ответов с
помощью. Ранее скачанные пакеты и их очереди остаются совместимыми; уже сохранённые
на устройстве старые ключи невозможно отменить обновлением сервера. Для нового
формата следует скачать новый пакет, сохранив старую очередь до синхронизации.

## Автоматические проверки

```powershell
npm run test:choices:unit
npm run test:choices:http
npm run test:choices:browser
npm run test:choices:migration
npm run test:choices:math
npx tsc --noEmit
npm run build
```

HTTP, миграция и браузер используют временные аккаунты и удаляют свои данные.
Миграционный тест запускайте последовательно, отдельно от остальных: его SQL
получает блокировку таблиц, а проверка сохранности сравнивает число записей.
Для HTTP/браузера нужен сервер на `127.0.0.1:3100`, либо `CHOICE_TEST_BASE_URL`.
Для браузера нужен установленный Chromium Playwright. Математический аудит
использует Python/SymPy 1.13.3 (`CHOICE_AUDIT_PYTHON` позволяет выбрать Python),
проверяет фактический банк независимыми формулами, отсутствие равнозначных
вариантов и ровно один правильный ответ. Нераспознанное учебное содержание не
дополняется случайными вариантами и не попадает в новую тренировку.

Команды `test:progress`, `test:session`, `test:offline:http` и
`test:offline:browser` используют общие проверки нового контракта A–E.
Старые файлы сценариев ручного ввода сохранены как описание исторического API.
Интеграционные проверки авторизации, диагностики, плана и экзамена адаптированы;
их unit-проверки и проверки офлайн-очереди сохранены.
