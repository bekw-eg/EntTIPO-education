# Этап 6.2: экзаменационный математический блок

Реализовано и проверено 05.10.2026 на основе профиля этапа 6.1
`ntc-tipo-b057-math-2023@1.0.0`. Страница `/exam` показывает профиль,
источники, язык, формат, время и оценивание до запуска; `/exam/:id`
возобновляет вариант или открывает сохранённый результат.

## Официальный формат и учебные настройки

Параметры `official` исходного профиля не изменены: 20 заданий,
`single_choice_4`, один ответ из четырёх; A/B/C = 5/10/5; правильный ответ
1 балл, неправильный и пропуск 0, максимум 20. Частичных баллов в этом
профиле нет. Числовой ответ, выражение, множественный выбор и многошаговые
тренировочные задачи не допускаются в экзамен; новый официальный формат
потребует отдельного проверенного профиля и оценивания.

НЦТ не опубликовал отдельный лимит математики и тематические квоты в
проверенных источниках. Они остаются `null`. **120 минут относятся ко всему
ЕНТ из двух дисциплин**, а не к математике. Перед началом ученик выбирает
**учебный лимит платформы 30, 40 или 120 минут**; по умолчанию 40.
Он явно отделён от нормативов НЦТ и сохраняется вместе с вариантом.
Переходы, изменение ответа, очистка ответа и отметки «вернуться позже» —
политика учебной симуляции до её завершения, не заявление о неизвестных
правилах интерфейса НЦТ.

Из этапа 6.1 используется внутренний баланс: по одному заданию на каждый
из 20 пунктов. Алгоритм максимального потока одновременно удовлетворяет
квотам сложности и пунктов; порядок кандидатов и готового варианта
перемешивается на сервере. Отбор допускает только актуальные прямые
предметные проверки текущего профиля/версии, один закрытый шаг с четырьмя
разными вариантами, единственным согласованным эталоном, уровнем A/B/C и
явными связями навыков вопроса и шага. Одинаковые отпечатки содержания
не повторяются в варианте, семейство имеет один основной пункт.

Для недостающих пунктов 12, 15, 16 добавлены три авторские задачи:
линейность интеграла (B), разделяющееся ДУ с начальным условием (C),
ДУ второго порядка с двукратным корнем и двумя начальными условиями (C).
SymPy проверяет все 33 авторские задачи, включая полные решения обоих ДУ,
начальные условия, единственность верного варианта и границы областей.
Для подготовки добавлены конкретные правила по всем 20 навыкам.

После дополнения банк содержит 508 задач; 33 пригодны для этого профиля.
Все 20 пунктов имеют представителя в экзаменационном формате. Можно собрать
один полный сбалансированный вариант; три независимых варианта по политике
аудита недоступны. Исчерпывающее покрытие широких пунктов и статистическая
калибровка сложности по-прежнему не подтверждены. Русский банк проверен;
казахский экзамен не предлагается до проверки перевода. При недостатке
актуальных кандидатов сервер отвечает 422 с пунктами и дефицитом сложности;
неподходящая задача не заменяет отсутствующую.

## Состояние, время, сеть и безопасность

`ExamSession` хранит профиль и его версию, язык, выбранный учебный лимит,
неизменяемый снимок всего варианта с эталонами и объяснениями, идентификаторы,
ответы индексами 0–3, текущую позицию, отметки, ревизию и последний запрос
сохранения. Изменение банка после старта не меняет задачи или оценивание.
Снимок варианта приватен; API активного экзамена отдаёт только явный список
публичных полей, без эталонов, объяснений, признаков правильности и подсказок.
Публичные и личные API не кэшируются; существующий service worker также
не кэширует личные API/HTML/RSC.

`startedAt` берётся из PostgreSQL `clock_timestamp()` **после** блокировки
аккаунта и подготовки варианта. `deadlineAt` один раз вычисляется сервером.
`NOW()` не используется: это время начала транзакции, которое могло бы
предшествовать ожиданию блокировки. Клиент не может передать начало,
срок или остаток времени ни в старт, ни в сохранение. Схемы строгие.
Отсчёт на экране использует `performance.now()`, а не часы браузера;
каждые 10 секунд и при возврате на страницу он сверяется с сервером.

Все чтения/сохранения/завершения экзамена сериализуются блокировкой строки
аккаунта; каждый запрос проверяет владельца. Чужой идентификатор даёт 404.
На аккаунт допускается один активный экзамен; SQL дополнительно содержит
частичный уникальный индекс. UUID запуска связывается с хешем настроек:
повтор не создаёт другой экзамен, смена настроек с тем же UUID даёт 409.
UUID последнего сохранения и хеш позволяют повторить потерянный ответ;
устаревшая ревизия даёт 409 и не перезаписывает другую вкладку.
Ответ, отметка и позиция сохраняются одним запросом. Неподтверждённый запрос
дополнительно сохраняется в localStorage с ключом аккаунт/экзамен для
восстановления после обновления; без доступного хранилища серверное
сохранение продолжает работать. Экран показывает неполученное подтверждение
и предлагает безопасный повтор либо загрузку серверной версии.

Выход, обновление страницы, потеря сети и изменение часов не продлевают срок.
Поздний PATCH оценивает уже сохранённые ответы и возвращает завершённый
снимок, не применяя опоздавшие изменения. Таймер экрана инициирует чтение
при нуле. Если браузер закрыт, просроченный экзамен оценивается при ближайшем
серверном чтении, списке экзаменов или запросе завершения. Отдельного фонового
планировщика нет; срок при этом истекает независимо от браузера, завершение
фиксируется временем `deadlineAt`, поздние ответы не принимаются.

Пока экзамен не завершён, сервер запрещает AI, включая свободный чат без
questionId, подсказки в старых тренировках, `/api/attempts` (также повтор
уже отправленной попытки), чтение тренировочных разборов и ошибок, API
навыков и плана. Страница правила возвращает к активному экзамену.
Дашборд использует список безопасных полей и не сериализует эталоны или
старые `submissionResult`. Старый экзаменационный разбор недоступен во
время нового экзамена, чтобы не раскрыть повторяющийся вопрос.
Просроченный экзамен сначала нужно открыть/завершить; помощь остаётся
заблокированной до сохранения результата. Уже известные ученику материалы
и помощь вне платформы не могут быть отозваны.

`POST /api/exams/:id/finish {}` оценивает **сохранённые** ответы. Клиент сначала
подтверждает ожидающее сохранение, затем завершает. После потери ответа можно
повторить POST. Результат, наблюдения навыков и ошибки записываются в одной
транзакции. Проверка `status=completed`, блокировка аккаунта и уникальность
наблюдения экзамен/задача/навык предотвращают дубли. Любой повтор завершения
возвращает сохранённый результат, в том числе после автоматического истечения.

## Баллы, Mastery Score, статистика и план этапа 5

Баллы вычисляются по сохранённому `official`: сравнение одного выбранного
варианта с эталоном даёт 1/0, пропуск 0. Процент правильных тренировочных
шагов не используется. В сохранённый результат входят баллы/максимум,
разбиение по темам/навыкам, ответы и объяснения всех заданий, пропуски,
конкретные пункты для подготовки и ссылки на правило, тренировку и план.

Экзамен отделён от `PracticeSession`/`UserAttempt`. Он **не увеличивает**
число решённых тренировочных задач, тренировочные попытки, точность,
дневную цель, Streak и тематический Mastery Score тренировок. Его история
и баллы доступны в разделе экзаменов.

За каждое отвеченное задание записывается одно `SkillObservation` с
источником `examSessionId`: 100/0 внутренней шкалы наблюдения, без частичного
ответа. Mastery Score **навыка** пересчитывается существующим алгоритмом,
включая окно, давность, сложность, повторы и консервативные пороги доказательств.
Это педагогическая метрика, не экзаменационные баллы. Пропуск не создаёт
наблюдение или ошибку и не понижает Mastery как доказанное неверное решение.
Неверный ответ создаёт связанную с навыком ошибку с нейтральным типом
`unclassified`; точная причина не угадывается по одному выбору.

Ранее раскрытый в тренировке/диагностике/экзамене ответ либо зарегистрированная
помощь отмечаются в снимке как `previouslyExposed`. Экзамен по-прежнему начисляет
официальные баллы, но наблюдение получает консервативный флаг `usedHint` и
повышенный номер при повторном наблюдении. После экзамена все раскрытые задания,
включая пропущенные, исключаются из независимых проверок этапа 5. Повтор
такого вопроса в тренировке также получает флаг раскрытого ответа. Экзамен
не устанавливает `confirmedAt` и не выдаёт самостоятельную проверку за повтор.

План сохраняет `examId` источника. Ошибки и пропуски последнего экзамена
добавляют сигнал `exam_gap` (20 на пробел, максимум 60) к ранжированию навыков;
пропуски требуют подготовки, но не объявляются ошибками знания. После
полностью пропущенного блока план тоже предлагает конкретное правило,
практику и проверку, не создавая выдуманных наблюдений Mastery.
Неначатый план пересобирается по новым результатам; начатая работа
сохраняется и переносится по правилам этапа 5. В следующем плане учитывается
новый источник. Правило доступно даже при недостатке задач. Если нет трёх
задач практики или нового независимого проверочного вопроса, соответствующее
действие честно показывает нехватку; эталон экзамена не перерабатывается в
независимое подтверждение.

## Обновление и проверки

Остановить приложение; миграция повторяемая, без сброса данных:

```powershell
npx prisma db execute --file prisma/updates/20261004_exam_mode.sql --schema prisma/schema.prisma
npm run db:generate
npm run db:exam
npm run build
npm run start -- --port 3100
```

Основные проверки:

```powershell
npm run test:exam-mode:unit
npm run test:exam-mode
npm run test:exam:unit
npm run test:exam
npm run test:exam:math
npm run test:exam:http
```

HTTP-проверки по умолчанию используют 3100; альтернативу задаёт
`EXAM_TEST_BASE_URL`. Они создают свои аккаунты и удаляют только свои фикстуры.
Тест проверяет 20 разных пунктов и квоты, повторный вход, сохранённые
ответы/отметки/позицию, неизменный срок, запрет часов из клиента, чужие запросы,
обходы подсказок/AI/проверки, изменение банка после старта, пять параллельных
завершений, результат 12/20 с четырьмя пропусками, поздний ответ, закрытый
браузер, полностью пропущенный вариант, план и повторное применение SQL.

Регрессии `test:auth:unit`, `test:auth`, `test:progress:unit`, `test:progress`,
`test:session:unit`, `test:session`, `test:skills:unit`, `test:skills`,
`test:plan:unit`, `test:plan` запускаются против того же приложения.
Интеграционные наборы выполняйте последовательно: часть тестов сравнивает
глобальное число вопросов до/после сидинга. Новые модульные тесты также
проверяют отказ от неподдерживаемых форматов, все 20 тематических нехваток,
80 порядков кандидатов, приватность полей, локальное восстановление по
аккаунтам, монотонный таймер и планирование пропусков без ложного Mastery.
В браузере проверены запуск, выбор, отметка, переход, обновление и
завершение с результатом, темами, навыками и ссылками на подготовку.
