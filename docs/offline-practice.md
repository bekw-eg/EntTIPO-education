# Офлайн-практика — этап 6.4

Ссылка на `/practice` открывает публичную автономную оболочку
`/offline-practice.html`. С интернетом после входа ученик выбирает темы,
язык RU/KK и 1–50 заданий. Пакет перечисляет правила, материалы, задания,
язык, размер и версию. Темы представлены по очереди; заданий должно быть
не меньше числа выбранных тем. Каждый пакет содержит одно сохранённое
прохождение. Новая версия скачивается отдельно, сохраняя прежнюю работу.

## Полная загрузка и изоляция

`npm run offline:build` собирает отдельные публичные HTML/JS, KaTeX CSS
и все шрифты. Он выполняется перед `build` и `dev`. Загрузка проверяет
размер и SHA-256 каждого ресурса, пишет их в Cache Storage и только затем
атомарно публикует пакет в IndexedDB. «Доступно офлайн» появляется после
завершения записей. Список повторно проверяет целостность ресурсов, чтобы
обнаружить вытеснение кеша. При частичной загрузке пакет не объявляется
готовым; повтор с тем же downloadId возвращает ту же серверную тренировку.

IndexedDB `enttipo-offline-v1` хранит пакеты (`[userId, packageId]`),
черновики всех заданий и курсор (`[userId, sessionId]`), неизменяемые отправки
с квитанциями (`[userId, submissionId]`) и видимый аккаунт с постоянной
блокировкой доступа после выхода. Каждая транзакция проверяет владельца;
смена аккаунта сообщается другим вкладкам. Сервер проверяет владельца каждого
POST, включая гонку со сменой cookie. Паролей, токенов и серверных секретов
в IndexedDB нет. После выхода прежняя работа скрыта до повторного входа
владельца. Офлайн-выход блокирует доступ на устройстве даже при невозможности
отправить серверный logout; локальная блокировка хранится в IndexedDB.

Это изоляция интерфейса и API, а не защита от владельца браузерного профиля:
с DevTools/доступом к диску локальные данные можно прочитать. Для такой защиты
на общем устройстве нужны отдельные профили ОС/браузера. Минификация или
шифрование ключом из того же приложения не скрывают эталоны от владельца.

Service Worker не кеширует персональные HTML, RSC и API. Он поддерживает
публичную оболочку, явно скачанные публичные ресурсы и обычные статические
ресурсы. Производственный localhost поддержан для тестов. Кеш пакетов
сохраняется при обновлении SW и смене аккаунта: персональных данных там нет.
Неиспользуемые публичные ресурсы остаются в кеше; удаление пакета удаляет
персональную запись, а не общие шрифты.

## Честная граница оценки

Это отдельный режим `offline_practice` с доступными устройству эталонами.
Локально поддерживаются один вариант по ID, набор вариантов (JSON-массив ID),
конечные десятичные числа и простые дроби, запятая/точка, абсолютный допуск
`1e-9`, модуль исходных чисел до `1e12`. Символьные выражения, корни, степени,
`pi`, произвольные функции, неизвестные типы и неподдерживаемый числовой ввод
показывают «Ожидает проверки». Строковое или вероятностное сравнение выражений
не считается доказательством. Символьные эталоны в пакет не включены.

Все локальные результаты предварительные. Обычная онлайн-практика продолжает
выдавать эталоны только после проверки. Экзаменационные (`exam_v1_*`),
диагностические и контрольные задания исключены из экспорта. Сервер помечает
выгруженные задания как доступные с помощью (`QuestionHelp`); удаление пакета
не стирает факт доступа. Их нельзя затем использовать как независимое
подтверждение проработки ошибки.

Синхронизация вызывает общий серверный обработчик попыток с актуальными
эталонами БД и обычным математическим сервисом, включая существующий серверный
резервный движок. Клиентские оценки игнорируются. Только после серверной
проверки в транзакции обновляются Mastery, наблюдения навыков, ошибки и
дневной прогресс. Помощь принудительно учитывается даже при подмене клиентом.
Офлайн-работа не подтверждает независимую контрольную проверку: для неё нужно
новое онлайн-задание. Ограничения серверного движка остаются прежними.

## Очередь и восстановление

Ввод записывается в IndexedDB. «Сохранено на устройстве» появляется только
после завершения транзакции. При ошибке хранилища интерфейс предупреждает
при закрытии и позволяет экспортировать также видимые несохранённые значения.
Compare-and-swap локальной ревизии предотвращает перезапись второй вкладкой.
Курсор и черновики восстанавливаются после закрытия страницы. Сохранённый
вопрос доступен для просмотра; для нового прохождения скачивают другой пакет.

Нажатие проверки атомарно фиксирует UUID и полный ответ до обращения к сети.
До квитанции запись сохраняется с исходным UUID. Серверные уникальность
`[userId, submissionId]`, хеш ответа, блокировка аккаунта и результат в одной
транзакции обеспечивают повтор того же результата после потери ответа,
обрыва связи, перезапуска вкладки и параллельных запросов. Только квитанция
даёт состояние «Синхронизировано». Она остаётся на устройстве до удаления.

- Отправки идут по порядку внутри тренировки: при открытии офлайн-экрана,
  возвращении сети и каждые 15 секунд активного экрана. Закрытая вкладка
  не отправляет в фоне; работа продолжится при следующем открытии.
- При 401 показан повторный вход в сохранённый аккаунт. Смена владельца
  прекращает отправку, другой ученик не может отправить прежнюю очередь.
  Активный экзамен блокирует синхронизацию отдельно от истёкшей авторизации.
- Конфликт ревизий сохраняет ответы. Ученик может экспортировать их или
  явно принять текущее серверное состояние. Если другое устройство уже
  отправило другой ответ, осознанное продолжение создаёт отдельную попытку
  с первоначальным UUID этой отправки, не перезаписывая прежнюю попытку.
- Версия покрывает выбранные тексты, материалы, задания и эталоны. При её
  изменении очередь останавливается. Явное принятие позволяет перепроверить
  ответы по новым эталонам. При изменении ID/типов шагов или вариантов
  автоматическое сопоставление запрещено: нужны экспорт и отдельный пакет.
- Ревизия, принятие версии и разрешение конфликта — отдельные метаданные;
  они не меняют исходный UUID, ответ и его хеш.
- Удаление пакета с неотправленными ответами или непроверенным черновиком
  запрещено. Экспорт создаёт резервную копию, но не снимает блокировку.
  Обновление создаёт отдельный пакет и не уничтожает старую работу.

## Ограничения и развёртывание

Нужны HTTPS либо localhost, Service Worker, IndexedDB, Cache Storage и место
на устройстве. Браузер может отказать в `storage.persist()` или пользователь
может очистить данные сайта; приложение не восстанавливает удалённую локальную
работу. Для резервной копии есть экспорт JSON. При развёртывании желательно
сохранять прежние версионные файлы `public/offline-assets`, чтобы повторно
скачивать ресурсы старых пакетов после очистки кеша.

Перед запуском примените `prisma/updates/20261005_offline_practice.sql`
или соответствующую миграцию, затем `npm run db:generate` и `npm run build`.
Новая таблица OfflinePackage должна существовать до запуска приложения.
В этой задаче проверки выполнялись на отдельной временной БД; основная БД
не изменялась. Генерируемые публичные файлы исключены из Git и создаются сборкой.

Экзамен остаётся онлайн: серверные сроки, сохранение до дедлайна,
завершение и авторитетный результат не переносятся в локальную очередь.
Локальные часы и содержимое устройства нельзя считать достоверным источником
экзаменационных ограничений. AI без сети явно недоступен; скачанные материалы
работают без него. Обычные онлайн-тренировки автоматически в пакеты не превращаются.

## Проверки

```powershell
npm run db:generate
npm run test:offline:unit
npm run test:auth:unit
npm run test:session:unit
npx tsc --noEmit
npm run build
# Отдельная БД, уже созданная и согласованная со схемой:
$env:OFFLINE_TEST_DATABASE_URL = 'postgresql://test_user@127.0.0.1:5432/enttipo_offline_tests'
npx tsx scripts/run_offline_tests.ts
```

Последняя команда поднимает локальный production-сервер со случайным ключом,
запускает HTTP, Playwright (`setOffline(true)`), регрессионные проверки
сохранения, прогресса и изоляции аккаунтов, затем останавливает сервер.
Нужен Chromium: `npx playwright install chromium` или
`PLAYWRIGHT_CHROMIUM_EXECUTABLE`. По умолчанию также проверяется недоступность
микросервиса математики: сервер самостоятельно перепроверяет резервным движком.
`OFFLINE_TEST_MATH_URL` позволяет проверить с запущенным SymPy.
Тесты создают и удаляют только свои временные аккаунты/задания.

Покрыты полная загрузка, формулы, отсутствие сети, закрытие и восстановление,
сохранение UUID, потеря квитанции закоммиченной попытки, параллельные повторы,
отсутствие дубликатов Mastery, неподдерживаемая локальная проверка, 401,
смена аккаунта, офлайн-выход, конфликт, новые эталоны и защищённое удаление.
