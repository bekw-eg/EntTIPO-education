# Персональная программа подготовки

Работа основана на `cb843b7` (`feature/ui-polish-and-smoke-tests`). Новая ветка:
`feature/personal-preparation-program`. Незакоммиченная пользовательская правка
`AGENTS.md` не входит в изменение.

## Архитектура и состояния

| Требование | Использованный механизм | Изменение |
| --- | --- | --- |
| Диагностика | DiagnosticSession / DiagnosticAnswer, UUID, локальный черновик, серверная ревизия, StepSkill | Исходные 9 вопросов плюс по одному подходящему заданию для ещё не охваченных размеченных навыков; приватный снимок содержания; создание программы в транзакции завершения |
| Профиль знаний | SkillObservation, calculateSkillProgress, readUserSkills | Прежняя модель Mastery сохранена; один ответ остаётся insufficient; помощь и повторное раскрытие учитываются |
| Стабильный маршрут | LearningRoadBlock / LearningRoadNode, явный SKILL_PREREQUISITES | Версия, сохранённая политика, полный цикл SKILL / MIXED / FINAL, обязательные зависимости внутри программы |
| Контроль | ExamSession, private paper, server clock, CAS revision, gradeExamQuestion | Короткие A–E проверки из существующих choice snapshots; штатный полный четырёхвариантный финал |
| Закрепление | PracticeSession, makeChoiceSnapshots, QuestionCard, правила | Целевая практика только по проваленным навыкам; новый независимый контроль после практики |
| Повторение | SkillReview, nextReview | Те же интервалы 1/3/7/14 и версия расписания, обновление при контрольной точке |
| История и offline | UserAttempt, submission UUID, offline packages / sync | Существующее оценивание и очередь сохранены; offline может выполнить учебный шаг, но не подтвердить контроль |

Основные состояния главной: `diagnostic_needed`, `diagnostic_active`,
`road_ready`, `learning`, `mixed_ready`, `final_ready`, `assessment_active`,
`reinforcement`, `completed`, `content_shortage`.

```text
диагностика → программа → SKILL.check
                         ├─ успех → следующий этап
                         └─ неудача → repair → practice → check на новых задачах
каждые 3 SKILL → MIXED (последняя неполная группа тоже проверяется)
все SKILL/MIXED подтверждены → FINAL
FINAL → нет пробелов: completed
      → есть ошибки/пропуски: новый цикл по этим навыкам и необходимым основам
```

`GET /api/preparation` создаёт программу для старого пользователя с завершённой
диагностикой, если её ещё нет. Это выполняется под существующей блокировкой строки
аккаунта. Перезагрузка, смена языка, календарная дата или обычная тренировка не
перемешивают маршрут. Завершение новой диагностики не переписывает начатый цикл.
Исторические программы, узлы, экзамены и результаты сохраняются.

`POST /api/preparation` принимает только `nodeId`, `action=check|practice`,
`requestId` UUID. Сервер проверяет владельца, текущую программу, порядок этапов,
зависимости и фазу. Нельзя начать финал прямым запросом до выполнения критериев.
Свободный `/exam` остаётся отдельной учебной возможностью; его результаты не
обходят доступ к финалу программы. Старый endpoint learning-road принимает
только узлы с `programVersion=0`, поэтому не может пропустить новые проверки.

Повтор UUID запуска возвращает тот же экзамен и проверяет хеш параметров.
Несколько UUID при одновременном запуске возвращают один активный экзамен.
Повторные завершения возвращают сохранённый результат; следующая программа
дополнительно защищена уникальным `sourceExamId`. Оценивание экзамена, наблюдения,
исход узла, расписание повторений и следующий цикл записываются атомарно.

## Правила подтверждения

Настройки находятся в `lib/learning-road/program-policy.ts`. Копия настроек
сохраняется в `LearningRoadBlock.policy`: обновление конфигурации влияет на
новые циклы, а не незаметно меняет требования уже начатой программы.

| Настройка | Начальное значение | Назначение |
| --- | --- | --- |
| Короткая проверка | 4 задания, ≥75%, ≥3 самостоятельных верных ответа | Несколько разных наблюдений вместо одного удачного выбора |
| Смешанная проверка | После 3 блоков, 2 новых задания на навык | Недавние навыки плюс 1 ранее подтверждённый навык из предыдущей группы |
| Успех смешанной проверки | Оба ответа верны по каждому проверяемому навыку | Не маскировать локальный пробел общим средним |
| Закрепление | 3 задания на проблемный навык | Разбор/правило и небольшая целевая практика перед новой проверкой |
| Время контрольной | 2 минуты на задание | Учебный таймер, без заявления о нормативе ЕНТ |
| Финал | Штатный вариант 20 заданий; учебные 40 минут; ≥80% | Существующий профиль и серверное оценивание |

Это начальные продуктовые эвристики. Они **не откалиброваны научно**, не дают
прогноза официального балла и не изменяют прежний алгоритм Mastery. Подтверждение
блока — сохранённый факт достаточного результата проверки, а не обещание полного
или постоянного владения всем содержанием навыка.

Уже `mastered` навык без наступившего повторения получает зачёт блока при
первом построении: прежний Mastery требует ≥5 разных недавних задач и ≥4
самостоятельных первых верных решений, а также балл ≥85. Основание зачёта
сохраняется как `existing_mastery`. Смешанные проверки всё равно обязательны.

Контрольный подбор исключает прежние попытки, DiagnosticAnswer, QuestionHelp,
hintedQuestionIds, вопросы всех сохранённых экзаменов и pending LearningCheck.
Также исключаются одинаковые условия после удаления пробелов и `$`, включая
условия из исторических snapshots. Алгебраически эквивалентные формулировки не
распознаются как дубли — это ограничение текущей разметки банка. На каждый навык
обязательны совпадающие QuestionSkill, StepSkill и skillIds в practiceChoice.
Тренировка резервирует доступные задания следующей проверки и отдаёт приоритет
уже раскрытым задачам для разбора и закрепления.

Для новых A–E контролей ExamSession сохраняет PracticeChoice с непрозрачными
ID вариантов и однажды установленным порядком. Индекс ответа экзамена относится
к этому неизменяемому порядку; правильный индекс определяется по correctOptionIds.
Публичный serializer не отдаёт private choice, эталоны или объяснение. В обычном
экзамене по-прежнему допустимы только индексы 0–3; проверка длины фактического
варианта производится сервером даже при общей схеме сохранения 0–4.

При неудаче SKILL или MIXED успешные узлы не обнуляются. В текущем узле
сохраняются `repairSkillIds`, затем создаётся обычная практика. На контрольной
точке будущим связанным узлам записывается причина `checkpoint_gap`; начатые
сессии и порядок не меняются. Повторный MIXED снова проверяет весь свой набор
навыков на новых задачах. После финала любая ошибка или пропуск назначает
целевой цикл, даже если общий результат выше 80%; зачёт финала и оставшиеся
приоритеты — разные факты. Пропуск не создаёт ложного наблюдения ошибки.

## Интерфейс и совместимость

Главная показывает этап, подтверждённые навыки, число блоков до пробника и
одно главное действие. План дня остаётся в раскрывающемся разделе. Новый
`/learning-road` показывает программу; прежние короткие занятия доступны по
`/learning-road?legacy=1`, включая возврат из старых правил и сессий.
Каталог, свободная практика, статистика, история и экзамены сохранены.

Новые строки находятся в `lib/i18n/preparation.ts` для RU/KK/EN. Интерфейс
диагностики дополнен EN; учебный контент EN использует прежний RU fallback.
Общие Header, Card, Button, Progress, KaTeX и мобильная навигация переиспользованы.
Результаты диагностики отдельно показывают сильные стороны, приоритеты и
«Начать подготовку». Отсутствие наблюдений не показывается как слабость.

Во время диагностики недоступны помощь и параллельные обучающие проверки.
Чтение профиля навыков для восстановления самой диагностики разрешено, но без
текста правил, объяснений и рекомендаций. Сохранены прежние ограничения активного
экзамена, в том числе запрет раскрывать ответы старых попыток во время нового.

## Обновление данных без сброса

Остановить приложение, сделать обычную резервную копию и выполнить:

```powershell
npx prisma db execute --file prisma/updates/20261007_preparation_program.sql --schema prisma/schema.prisma
npm run db:generate
npm run build
```

SQL повторяемый и транзакционный. Добавлены только поля существующих сущностей:
`DiagnosticSession.questionSnapshots`; версия/политика/статус/причина/источник в
LearningRoadBlock; фаза/список навыков/навыки закрепления/основание результата в
LearningRoadNode; nullable FK `ExamSession.roadNodeId`. Новых параллельных таблиц
mastery, попыток или программы нет. Старые блоки получают `programVersion=0`.
Старые диагностики без snapshots продолжают читать банк прежним способом.
Попытки, UUID, очереди offline, старые ответы и choice snapshots не переписываются.

В этом задании рабочая БД из `.env` не изменялась. Для проверки создан отдельный
локальный PostgreSQL на 55467 с базой `enttipo_preparation_test_20261007` и
штатными seed/skills/exam. Docker и рабочий сервер БД были недоступны.

## Проверки

```powershell
npm run lint
npm run typecheck
$env:NEXT_BUILD_DIR = '.next-smoke'
npm run build
$env:PREPARATION_TEST_DATABASE_URL = '<URL изолированной локальной тестовой БД с test в имени>'
$env:EXAM_AUDIT_PYTHON = 'python' # необязательно: локальный SymPy вместо Docker
npm run test:preparation
```

Runner запускает production Next на 3100, последовательно выполняет наборы
`new units integration browser regression`, сохраняет логи в `tmp/preparation/`
и останавливает свой сервер. Он не применяет seed/reset к переданному URL.
Схема и банк отдельной БД должны быть подготовлены заранее. Каждая фикстура
удаляет только созданные ею аккаунты и контент.

`test:preparation:unit` проверяет независимые доказательства, insufficient/weak,
пороги, смешанные пробелы, порядок/циклы prerequisites, публичный whitelist и
сохранение четырёхвариантного оценивания. HTTP проверяет реальную регистрацию,
диагностику по банку, создание/восстановление маршрута, выдачу зачёта существующему
mastered, доступ/изоляцию, UUID/конкурентность, варианты после помощи, неудачу и
практику, смешанную проверку, финал и целевой следующий цикл, дефицит контента,
повторную миграцию и неизменность истории. Browser проходит те же основные
переходы через экран, восстанавливает ответы и снимает 360/390/768/1440px.

Полная механика программы проверяется на **явно синтетическом тестовом учебном
каталоге** с различными арифметическими заданиями, сохранёнными в настоящей БД
и проверяемыми настоящими API. Финал использует штатный реальный экзаменационный
банк. Отдельный сценарий проверяет штатную диагностику и полный штатный маршрут.
Это не доказательство достаточного разнообразия штатного банка для прохождения
всех его навыков: при дефиците новые проверки намеренно остаются недоступными.

## Ограничения

- Банк конечен. У ряда экзаменационных навыков недостаточно новых размеченных
  заданий для четырёхвопросного блока, повторного контроля и смешанных проверок.
  Программа показывает нехватку и сохраняет прогресс; она не выдаёт фиктивный
  зачёт и не создаёт неподтверждённые варианты ради возможности пройти дальше.
- Входная диагностика шире исходных трёх навыков, но один вопрос на остальные
  навыки даёт только начальный сигнал. Непокрытые навыки остаются insufficient.
- Поддерживается существующий явно заданный граф prerequisites. Отсутствующая
  связь не выводится автоматически из названия темы.
- Расписание повторений живёт в прежнем SkillReview; завершённая программа
  рекомендует продолжать повторения, а не запускает ежедневный новый финал.
- Финальный вариант может содержать ранее встречавшиеся задачи. Это показано
  в отчёте и не даёт независимого Mastery; разнообразия для нескольких полностью
  новых полных экзаменов пока недостаточно.
- Контрольные точки требуют сервер. Offline предназначен для обучения.
- Проверки браузера — Chromium, без заявления о полном аудите WCAG или Safari.
- Существующие 13 предупреждений React hooks сохранены; новых предупреждений
  в компонентах программы нет.
