# Проверенный банк ЕНТ ТиПО B057

Дата проверки: 10 октября 2026 года. Профиль: родственное направление B057 «Информационные технологии», сокращённый срок обучения после ТиПО. Это авторский тренировочный банк, а не официальный комплект вопросов НЦТ.

## Программа и источники

На [странице подготовки НЦТ](https://testcenter.kz/?page_id=16208&lang=ru) повторно проверен действующий архив B057. Извлечённый «Математика.pdf» совпадает с сохранённым оригиналом `public/exam-sources/ntc-b057-math-2023.pdf`: SHA-256 `c8f2084cdce0788678178f8e0a05c91cb43a64d58e010589282bde4bb22284f7`. В документе указан 2023 год; отдельная редакция 2026 года не обнаружена. Сохранены 20 заданий, четыре ответа с одним правильным, A/B/C = 5/10/5, оценка 1/0. [Страница формата НЦТ](https://testcenter.kz/?page_id=16204&lang=ru) относится к сокращённому ЕНТ: 120 минут — весь экзамен из двух дисциплин, а не официальный лимит отдельного математического блока. Настройка по одному вопросу на каждый из 20 пунктов — политика Synaq, не квота НЦТ. Подробная исходная привязка: [exam-specification-coverage.md](exam-specification-coverage.md).

## Методика и доказательства количества

Исходный снимок: [exam-bank-before.json](exam-bank-before.json). До работы в БД было 508 вопросов, 223 разных отпечатка содержания; к экзамену допускались 33 уникальных задания на русском. Отдельный полный аудит KK до первой партии не сохранён, поэтому исходную готовность KK не утверждаем по общему числу строк.

Пилот: 240 кандидатов (60 шаблонов × 4), независимая математическая проверка, первоначально 216 приняты и 24 исключены по ключам; в [exam-bank-pilot.json](exam-bank-pilot.json) зафиксировано 249 доступных RU и 249 KK. Затем проверка стала строже: объединены равносильные обратные тригонометрические уравнения, совпадающие множества тригонометрических решений; вычисление значения функции само по себе не засчитывается как достаточное покрытие её свойств и графика. Поэтому статус пилота не заменяет итоговый аудит.

Финальная партия: 2 772 кандидата, 63 шаблона × 44 параметра. Проверяющий код не импортирует код формул ответов генератора: он заново вычисляет их через SymPy, решает уравнения на допустимых множествах, проверяет производные и начальные условия ДУ, сравнивает все шесть пар вариантов ответа и требует ровно один правильный ответ. Проверены все параметры 1–44, включая оба края диапазона. Решения и RU/KK тексты связаны с проверкой SHA-256 сертификатом; изменение содержания, вариантов, ключа, сложности или статуса снимает допуск до повторной проверки.

2 204 новых задания прошли допуск; 436 исключены как дубликаты, 132 математически корректных задания оставлены вне допуска из-за недостаточного соответствия пункту. Кроме того, четыре эквивалентности между старым и новым банками объединены в `LEGACY_MATH_ALIASES`. Число записей, включая сохранённые старые и выведенные из допуска строки, не является размером доступного банка. Для допуска KK тексты условия, решения и вариантов в БД должны точно совпадать с проверенным двуязычным артефактом; заполненное, но изменённое поле перевода допуска не получает.

Итоговый [exam-bank-after.json](exam-bank-after.json) получен непосредственно из БД через тот же `readExamAvailability`, что использует сервер. Для каждой представленной пары «пункт/сложность» проверено включение задания в полный допустимый вариант. Файл содержит отдельные результаты RU/KK, 20 пунктов, A/B/C, каталог семейств и измерение времени. Числа семейств считаются отдельно от количества параметрических вариантов.

## Отсутствие повторов и исчерпание

`ExamSession` — авторитетный журнал резервирования. Под блокировкой строки пользователя сервер читает **все** его попытки без фильтра статуса, языка или версии профиля; исключает ID, отпечатки, канонические математические ключи и нормализованные условия старых снимков. Создание с зафиксированным набором и резервирование — одна транзакция. Старые попытки без `mathKey` учитываются через ID, текущий реестр эквивалентностей и замороженное условие; реестр сохраняет даже отозванные алиасы.

Одна активная попытка сохраняет прежний набор. `ExamStartRequest` запоминает также запрос второй вкладки, который продолжил существующий экзамен: повтор этого запроса после завершения не создаёт другой экзамен. Изменение настроек с прежним requestId вызывает конфликт. Семейство не повторяется внутри варианта; между вариантами приоритет получают менее использованные семейства. Похожие параметрические задачи всё же возможны.

При дефиците сервер отвечает 422 и сохраняет подробный `ExamBankAudit` вне откатываемой транзакции отказа. Старые задания не возвращаются в выборку; история автоматически не сбрасывается. Сохранённые результаты остаются доступны. Отдельного статуса «брошен» схема не вводит: незавершённый снимок уже резервирует вопросы, а истечение срока завершает попытку по существующему правилу.

`maximumPapers` в отчёте — максимальная вместимость для нового аккаунта при оптимальном распределении с темами и A/B/C. Она вычисляется целочисленным потоком, проверенным независимым полным перебором 81 малого банка. `simulatedPapers` — один прогон текущего выбора; случайные предыдущие варианты могут исчерпать нужную сложность раньше максимума. Это конечный запас, а не обещание неограниченного числа пробников.

## Безопасный импорт и эксплуатация

1. Применить добавляющий SQL: `npx prisma db execute --schema prisma/schema.prisma --file prisma/updates/20261010_exam_bank_audit.sql`.
2. Обновить клиент: `npm run db:generate`.
3. Выполнить `npm run db:exam`. Партии по 25 заданий, стабильные ID, транзакции и advisory lock; повтор или возобновление не создаёт дубликаты. Конфликт содержания останавливает импорт. Разрешена узкая проверенная корректировка сложности; замороженные экзамены не переписываются.
4. Проверить `npm run exam:bank-audit` отдельно от тестов, временно меняющих данные.

Не требуются reset, удаление пользователей, ответов, результатов или старых вопросов. Уже существующий индекс `ExamSession(userId,status)` поддерживает поиск всей истории по ведущему `userId`. Добавлены индексы аудита и алиасов запусков. Полный JSON банка импортируется серверными модулями и не передаётся клиенту; активная попытка получает только публичные поля своих 20 задач.

Воспроизводимость: Python с SymPy из `entTIPO_math`, `scripts/build_verified_exam_bank.py 44` и находящийся рядом `verify_generated_exam_math.py` создают проверенный JSON. `npm run test:exam:generated-math` заново проверяет сохранённый артефакт; переменная `EXAM_MATH_PYTHON` позволяет использовать локальный Python с SymPy. Диапазон генератора намеренно ограничен проверенными параметрами 1–44. Новые шаблоны требуют нового содержательного и математического аудита.

## Ограничения

Сложность A/B/C назначена содержательной проверкой; эмпирической калибровки на учениках нет. RU/KK написаны парными шаблонами с одинаковыми числами, выражениями, ответами и решениями; независимая редактура носителем казахского языка не выполнялась. Символьная проверка подтверждает математическую часть, а не литературное качество перевода. Представленность всех 20 пунктов не означает исчерпывающего покрытия каждой возможной подтемы: для углубления всё ещё нужны дополнительные способы решения. Канонические ключи проверены для текущих шаблонов и известных старых эквивалентностей; произвольные будущие переформулировки требуют отдельного сопоставления. Совпадающие численные операции намеренно могут объединяться консервативно даже в разных контекстах: это уменьшает, а не завышает доступное количество.
